# Product Requirements Document (PRD) Template

## Problem and Context
- Description of the problem being solved.
- Relevant business or user context.

## Goals and Non‑Goals
- Measurable objectives.
- What is explicitly out of scope.

## Users and User Journeys
- Primary user personas.
- Key user journeys (steps users take to achieve goals).

## Scope and Out‑of‑Scope Behavior
- Features and behaviors included.
- Features and behaviors explicitly excluded.

## Functional Requirements
Each requirement gets a stable ID (e.g., FR-001).
- **ID**: Unique identifier.
- **Description**: Specific, observable system behavior.
- **Acceptance Criteria**: Testable conditions that must be met.
- **Associated User Journey(s)**: Which journey(s) this requirement supports.
- **Dependencies**: Other requirements or components it relies on.
- **Traceability**: Link to source evidence, decision, or design.

## UI States and Interactions
- Description of UI states (loading, empty, error, success).
- Interaction patterns.

## Data Behavior and Validation
- Data inputs, outputs, storage.
- Validation rules.

## Roles, Permissions, and Authorization Expectations
- Who can do what.
- Authentication and authorization requirements.

## Errors, Empty States, Loading States, Retries, and Recovery
- How the system handles failures.
- Retry strategies.
- Recovery procedures.

## Integrations and External Dependencies
- External APIs, services, libraries.
- Contracts and expectations.

## Relevant Non‑Functional Requirements
- Performance, scalability, reliability, usability, accessibility, security, privacy, etc.

## Analytics and Observability Needs
- What metrics, logs, traces are needed.

## Dependencies, Risks, Assumptions, and Open Questions
- Technical and product dependencies.
- Identified risks.
- Assumptions made.
- Open questions needing resolution.

## Source References and Traceability Matrix
- Links to evidence, design documents, decisions, test cases.

## Test Considerations
- Unit, integration, end‑to‑end test ideas.
- Test data requirements.

## Release Considerations
- Rollout strategy.
- Rollback plan.
- Post‑release monitoring.
