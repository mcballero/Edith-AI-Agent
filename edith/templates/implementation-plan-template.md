# Implementation Plan Template

## Milestones and Vertical Slices
- Milestone 1: Goal, target date, included features/components.
- Milestone 2: ...
- Each milestone should represent a coherent vertical slice (end‑to‑end functionality) that can be verified independently.

## Tasks and Dependencies
For each task:
- **ID**: Unique identifier (e.g., T-001).
- **Description**: Specific, verifiable work item.
- **Owner**: Person or team responsible (if known).
- **Dependencies**: Other task IDs that must be completed first.
- **Estimated Effort**: Rough estimate (e.g., story points, hours).
- **Acceptance Checks**: How we will know the task is done (test cases, criteria).
- **Risks and Unknowns**: Potential blockers or uncertainties.

## Acceptance Checks
- Test cases linked to requirements.
- Manual verification steps.
- Performance benchmarks.
- Security checks.

## Test Coverage
- Target coverage levels (unit, integration, end‑to‑end).
- Tools and frameworks to be used.
- Test data management.

## Risks and Unknowns
- Technical risks (performance, scalability, third‑party).
- Product risks (user adoption, market fit).
- Mitigation strategies.

## Suggested Ownership (when known)
- Mapping of components or modules to teams/individuals.

## Definition of Done
- Code written and reviewed.
- Unit tests passing.
- Integration tests passing.
- Documentation updated.
- Security and performance checks cleared.
- Deployed to a verification environment (if applicable).
- Acceptance checks satisfied.
